# Metis 个性化中心使用指南

## 1. 设计原则

个性化中心不预置任何研究场景。首次打开时，场景、智能体、技能、MCP 和
`Metis.md` 五个分类均为空。用户可以从空白开始创建，也可以安装或导入他人分享的
配置。

Metis 提供的是定义编辑器、版本系统和运行引擎，而不是替用户决定应当采用哪一种
期刊、论文、基金、专著或演示文稿工作流。

入口位于应用左下角，与主题按钮并列。窄屏下侧栏会收拢成图标栏。

## 2. 建议的创建顺序

虽然各类定义可以独立创建，但一个完整场景通常按以下顺序配置：

1. 创建或安装 Skill。
2. 创建或安装 MCP，并根据需要保存凭据。
3. 创建 `Metis.md` 规则。
4. 创建 Agent，绑定 Skill、工具、MCP、记忆和输出要求。
5. 创建 Scenario，选择以上定义并编排工作流。
6. 在对话页选择该场景并开始任务。

对话页默认保持“未选择自定义场景”，即使用户已经创建了场景，也不会偷偷选中第一个。
用户可以手动选择；未手动选择时，如果消息命中用户自己填写的触发短语，Metis 会启用
匹配短语最长的场景。没有命中时仍作为普通研究对话运行。

## 3. 创建场景

打开“场景”分类，选择“新建”。新场景会立即作为用户定义保存为第一个修订版本。

### 基础信息

- 名称
- 说明
- 是否启用
- 场景能力
- 触发短语

### 依赖

选择器只显示用户创建或安装的定义，并使用名称而不是内部 ID：

- 用于场景的智能体
- 场景可用的技能
- 场景可用的 MCP
- 场景专属 `Metis.md`

全局 `Metis.md` 自动参与解析，不需要在每个场景重复选择。项目规则由当前项目独立
管理。

### 工作流

每个步骤可配置：

- 步骤名称与目标
- 使用的 Agent
- 使用的 Skill、工具和 MCP
- 前置步骤
- 最大运行轮次

步骤依赖构成一个明确的执行图。只有场景已经选择的 Agent、Skill 和 MCP 才能进入
工作流步骤。运行前，步骤会自动继承执行 Agent 已绑定的 Skill、MCP 和工具，以及
这些 Skill 所依赖的 MCP 工具。不同步骤只加载各自的 Agent 与有效 Skill 提示词，
不会把其他步骤的角色指令混在一起。一个步骤的工作流也会进入同一套可恢复执行链。

### 记忆

- 记忆范围：无、会话、项目或场景
- 是否保留关键决策
- 是否保留产物
- 摘要字符上限

场景记忆和步骤 Agent 的记忆策略会共同生效。运行时只读取同时满足两层范围的已完成
工作流记录，并按开关加入以前的步骤输出和产物引用；最终上下文受较小的摘要上限约束。

### 输出计划

- 输出格式
- 主交付物
- 配套产物，每行一项
- 质量标准，每行一项
- 可选结构化输出 schema

输出计划会编译进冻结的运行提示，包括交付物、配套产物、质量标准、格式和可选 schema。
来源、证据、更正和发布状态仍由系统运行层判断。

### Full Access

场景使用 Full Access 时不会在每个工具动作前弹出确认框。用户仍可以在运行中发送
消息进行引导，或直接打断任务。

## 4. 创建 Agent

Agent 是可在多个场景间复用的工作角色。编辑器开放：

- 角色名称
- 系统指令
- 可选模型偏好
- Skill、工具和 MCP
- 记忆策略
- 输出格式、主交付物、配套产物和质量标准
- 最大轮次和重试次数

Agent 不需要对应某种固定学术身份。用户可以按实际任务创建方法顾问、访谈编码员、
统计审稿人、档案史料校勘员、章节编辑或其他角色。

当步骤指定了模型偏好时，Metis 使用当前 Provider 的同一连接配置创建该模型的独立
AgentLoop；留空则使用全局模型。失败步骤只在 Agent 设定的重试次数内重试，步骤轮次
同时受步骤、Agent 和 Skill 的最大轮次约束。

## 5. Skill 的三种模式

### 直接编写 Markdown

选择“技能”后新建定义，在“技能 Markdown”中编写说明。适合不希望制作安装包的用户。

同时可以配置：

- 系统指令
- 工具和 MCP
- 最大轮次
- 输入字段
- 输出字段

输入和输出字段通过可视化行编辑：字段名、类型、说明、是否必填。Metis 自动生成严格
结构，不要求用户直接写 JSON。

### 上传技能包

技能包可以是 ZIP 或目录。入口必须包含 `SKILL.md`，并可携带：

- 脚本
- 引用资料
- schema
- 模板与其他资源

包内相对路径随定义一起保存。详见 [SKILL_PACKAGE_FORMAT.md](SKILL_PACKAGE_FORMAT.md)。

### 从 URL 安装

选择 URL 模式并提供支持的 HTTPS 或 GitHub 地址。可以填写预期版本或 SHA-256，安装
成功后会生成一个可编辑的 Skill 定义。

## 6. MCP 的两种模式

### 描述需求，由 Metis 构建

填写 MCP 名称和需求说明。托管构建器根据需求生成服务定义，安装成功后由主进程注册
和激活。

### 从 URL 安装

提供支持的 MCP 仓库或包地址。安装记录决定可执行程序、参数、工作目录和工具列表，
这些运行字段不会在普通界面中被替换成任意命令。

### 凭据

凭据通过独立的加密凭据区保存。MCP 定义只引用环境变量名称，不包含真实值。导出的
个性化配置包也不包含凭据。

## 7. `Metis.md`

规则支持三种范围：

- 全局：适用于所有场景
- 场景：只对指定场景生效
- 项目：只对当前研究项目生效

项目 `Metis.md` 使用当前项目工作区。切换项目后，编辑器会加载相应项目的内容；保存
冲突时保留用户草稿并提示选择。

旧版 `AGENTS.md` 会迁移到 `Metis.md` 管理链，用户原文不会被静默丢弃。

## 8. 版本、恢复、归档和配置包

- 新建定义保存为 `r1`。
- 每次“保存”或“保存新版本”都会产生新的修订版本。
- 版本历史可以恢复以前的用户版本。
- 归档不会把定义伪装成从未存在。
- 导出会包含所选定义及依赖图。
- 导入会恢复定义与相应资产，但不会导入凭据值。

正在运行的会话使用启动时冻结的修订快照。编辑定义不会在中途改变当前任务。

## 9. 在对话中使用场景

1. 打开对话模式。
2. 在场景下拉框选择一个启用的用户场景。
3. 输入任务并发送。
4. 运行期间可继续发送引导消息。
5. 需要停止时选择打断。

下拉框不会列出内部预置，也不会在空状态下自动选择场景。

## 10. 自动真实性层

用户可以修改行为、工作流、角色、工具、记忆和输出要求，但以下状态不由可编辑文本
直接声明：

- 来源身份和版本
- 证据是否已观察
- 更正或撤回状态
- 引用和产物的出处
- 是否达到发布条件

个性化界面会显示该机制自动生效，但不提供关闭开关。这不会增加逐步确认；它只保证
系统不会把未经验证的结果表述成已验证结果。

## 11. 常见问题

### 为什么首次打开什么都没有？

这是产品设计。Metis 不假设用户要写哪类文章或采用哪种方法。

### 能否把别人的场景导入后修改？

可以。导入后的用户定义可以继续创建新修订版本。

### 修改场景会不会改变正在运行的会话？

不会。当前会话使用冻结快照；新版本用于后续运行。

### 为什么复杂 schema 不能直接在可视化编辑器里展开？

界面会保留无法无损表示的复杂结构。只有用户明确选择替换时，才会改成简单字段结构。

### PPT 场景在哪里？

alpha.2 不提供 PPT 预置。该空间保留给后续由用户定义的模板拆解和版式系统。
